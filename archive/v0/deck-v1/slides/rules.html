Eight rules I build by

1

Write the workflow down first

Every agent began as a notebook page with the same headings.

2

Math in code, judgment in the model

If a number has to be right, a script computes it.

3

One owner per kind of data

Automations never read a mirror.

4

Cheap check first, stop early

Two quick checks decide whether the costly work runs.

5

Unattended means propose

Scheduled runs draft; sending is always my click.

6

Fail loudly

Real exit codes, stale flags, nulls instead of zeros.

7

Memory goes stale

Every fact records how and when it was verified.

8

Package it for someone else

Versioned plugins, modular skills, a setup wizard.

These are the rules that came out of building and breaking this system. Each one transfers directly to a client deployment. If I had to pick two for an FDE conversation: rule 2, keep anything that must be exactly right in deterministic code and give the model the parts where judgment and tolerance are fine; and rule 5, anything running without a human proposes rather than acts.
